# ADR-004 - Document Processing Service Architecture

Status: Accepted
Date: 2026-07-18
Owner: Architecture Board

## Decision

CedarPeak Systems will run the `document-processor` workload using ECS Fargate for the API and asynchronous worker, SQS for job buffering, RDS PostgreSQL for transactional metadata, and S3 for original documents.

## Why

The workload receives document uploads, stores the original object, records metadata, and performs CPU-heavy processing asynchronously. SQS separates request handling from worker execution and allows the worker fleet to scale independently from the API.

## Boundary and exception rules

1. The architecture choice does not override security policy or data-residency rules.
2. For Restricted-EU customer document content, the data-plane components that store or process document content must be placed in `eu-central-1` under SEC-04.
3. Control-plane services with no document content may remain in `ap-south-1`.
4. **Temporary staging exception:** until 2026-10-15, staging may use a public PostgreSQL endpoint only for integration testing of a legacy partner. This exception requires:
   - environment = `staging`
   - no customer document content
   - fixed partner source CIDRs allowlisted at the database security group
   - database remains encrypted at rest and requires TLS
   - exception is not valid in production
5. The staging exception expires automatically on 2026-10-15 unless a new approved ADR replaces it.

## Decision authority

If current Terraform state and intended design disagree, the service owner (`billing-platform`) and Platform Engineering must establish the intended state before a destructive reconciliation.
